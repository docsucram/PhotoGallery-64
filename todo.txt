Looking at `2019-01-27 13.04.39.mp4` in WLPG vs our app:
1. WLPG shows `Date taken: 27/01/2019 13:04`, while our app shows `23/03/2025 12:34` (because our video scanner fell back to filesystem `mtime` instead of reading the MP4 `mvhd` creation_time atom / XMP / filename).
2. WLPG shows `Rating: 4 stars`, while our app shows `0 stars` (because our scanner did not scan the `.mp4` container for an embedded `<x:xmpmeta>` packet or Windows `Xtra` rating block).
3. WLPG's right-hand `Information` section hides `Camera / Exposure / Aperture / Focal length / ISO` for videos and instead displays `Duration: 00:00:08`, `Bitrate: 11861kbps`, and `Frame rate: 30 frames/sec`.

Implement the following 4 fixes:

### 1. Fast MP4/MOV `mvhd` Creation Date, Embedded XMP & Filename Fallback (`src/workers/scanner_thumb_worker.py`)
In `extract_media_metadata(filepath, is_video)` when `is_video=True`:
1. **Embedded XMP Packet in Video Files:**
   - Check for a sidecar `.xmp` first; if none exists (or in addition), scan the video file's header/footer chunks (first 1 MB and last 1 MB) or ISO BMFF `uuid`/`meta` atoms for `b"<x:xmpmeta"` ... `b"</x:xmpmeta>"`. If found, pass those bytes to `parse_xmp_packet_bytes()` so ratings (`MicrosoftPhoto:Rating` / `xmp:Rating`), tags, captions, and `xmp:CreateDate` embedded in `.mp4` files by WLPG/Windows are extracted!
2. **ISO BMFF (`mp4`/`mov`/`m4v`) `mvhd` Creation Time Parser:**
   - Write a fast binary box walker `_extract_mp4_creation_time(filepath) -> int | None` using `struct` and `f.seek()` (never reading `mdat` media payloads into memory):
     - Walk top-level atoms (`>I4s`; if size == 1, read 8-byte `>Q` extended size).
     - When `b"moov"` is found, walk its child atoms to find `b"mvhd"`.
     - Read `version = data[0]`. If `version == 0`, unpack `>I` at offset 4 (`creation_time`); if `version == 1`, unpack `>Q` at offset 4.
     - If `creation_time > 2082844800` (Mac HFS+ epoch `1904-01-01 00:00:00 UTC`), convert to Unix epoch: `unix_ts = creation_time - 2082844800`.
3. **Filename Timestamp Fallback Before `mtime`:**
   - If neither XMP date nor `mvhd` timestamp is present, check the filename stem against standard camera timestamp regexes:
     - `(?:VID_|IMG_)?(\d{4})[-_.]?(\d{2})[-_.]?(\d{2})[\s_-]+(\d{2})[._:-](\d{2})[._:-](\d{2})` (matches `2019-01-27 13.04.39.mp4` -> `2019-01-27 13:04:39`!).
   - Only fall back to `stat.st_mtime` if XMP, `mvhd`, and filename regex all return `None`.
4. **Extract Video `duration_sec`, `fps`, and `bitrate_kbps`:**
   - Using `cv2.VideoCapture` (and `os.path.getsize(filepath)`), compute:
     - `fps = cap.get(cv2.CAP_PROP_FPS)`
     - `frame_count = cap.get(cv2.CAP_PROP_FRAME_COUNT)`
     - `duration_sec = frame_count / fps if fps > 0 else 0`
     - `bitrate_kbps = int((file_size_bytes * 8) / (duration_sec * 1000)) if duration_sec > 0 else 0`
   - Store `duration` (`float`), `fps` (`float`), and `bitrate_kbps` (`int`, or compute dynamically from `size` and `duration`) in `media`.

### 2. Display Video Properties in Right `Information` Pane (`src/ui/right_tag_dock.py`, `src/db/repository.py`)
- In `CatalogRepository.get_media_detail` (`src/db/repository.py`), include `is_video`, `duration`, `fps`, and computed `bitrate_kbps = int((size * 8) / (duration * 1000))` when `duration > 0`.
- In `RightTagDock` (`src/ui/right_tag_dock.py`):
  - When displaying a single video item (`is_video == True`), hide the photo-only rows (`Camera`, `Author`, `Exposure`, `Aperture`, `Focal length`, `ISO`) and in their place show:

    - `Frame rate:` formatted as `{fps:g} frames/sec` (e.g. `30 frames/sec`)
  - When displaying a photo (`is_video == False`), show the standard photo rows and hide the video-only rows.
